## Требования «сделать и показать», а не написать инфраструктуру
Построй полноэкранную адаптивную игру с оригинальным профессиональным UI, не выглядывающую из общей стилистики проверенной галереи:
1. Стартовый экран: имя (optional), ровно три режима **Конфликт / Переговоры / Конфликт + переговоры** (последний не путать со смешанным типом), тип конфликта личный/публичный/смешанный для обоих конфликтных режимов, сложность easy/medium/hard/extra_hard/impossible, роль пользователя **защитник / манипулятор** только в конфликтных режимах, сфера работа/семья/учёба/друзья/другое со своим текстом, рандомизация всего КРОМЕ имени и модели, кнопка начать. Режимы и роли должны сохраняться в session; при студенте-защитнике ИИ = `MODEL_MANIPULATOR`, при студенте-манипуляторе ИИ = `MODEL_DEFENDER`. В смешанном сценарии на высокой сложности эмоциональная эскалация вероятнее, но всегда причинна, не рандомный meltdown.
2. РОВНО ДВЕ модели на выбор в UI: **Claude Opus 5.5** (премиальный мощный Claude/GPT через OpenRouter; default model ID `anthropic/claude-opus-5.5`, альтернатива по ENV `openai/gpt-6-astra` + UI label GPT-6 Astra) и **Qwen3-8B · Дообученная** только при действующем реальном `LORA_BASE_URL`; если нет, второй вариант честно disabled — никакой ложной «демонстрации QLoRA». Выбранный движок ведёт ВЕСЬ игровой диалог, включая публичные групповые реплики, если они реализованы. НЕЛЬЗЯ запускать Qwen3-32B вместо премиальной Claude/GPT и НЕЛЬЗЯ переключить LoRA-игру на Claude по ходу.
3. Запуск: через server-side `POST /api/sessions` Claude/GPT CASE_MODEL создаёт *новую* ситуацию. Сделай строгую runtime JSON-схему для `public/world/opponent/teaching/category/scenario/difficulty` по существующей `schemas/case.schema.json`, но БЕЗ заранее написанного `dialogue` (TRAIN v1 требует 4 готовых сообщения; runtime не должен этого делать). Один retry/repair при ошибке + статический валидный fallback ТОЛЬКО из TRAIN, ни при каких обстоятельствах DEV/TEST. UUID сессии отдельно от IDs `C###`. Public/Private фильтр в ответе браузеру.
4. Игровой чат: слева имя персонажа, справа имя игрока; чистое форматирование, видимая карточка публичной обстановки/цели, `opponent.opening` первым, отправка и прокрутка, Enter/Shift+Enter, защита от повторной отправки, состояния загрузки и ошибок. Серверный `POST /api/sessions/{id}/message`, **отдельный** prompt roleplayer с world/public/opponent и строгим соблюдением hard_limits. ВЕСЬ разговор на одной выбранной в начале модели. Публика для публичных/смешанных кейсов в P0 показана сценой/именами; если добавишь самостоятельные сообщения публики — только тем же выбранным engine, без третьего API.
5. Кнопка **«Завершить» доступна ДОСРОЧНО на любом ходе**. Она **завершает игровую сессию без вызова Judge** (`POST /api/sessions/{id}/finish`), затем отдельное предложение «Хотите оценку по этому кейсу?» с кнопками **«Получить оценку» / «Без оценки»**. ТОЛЬКО явное согласие вызывает `POST /api/sessions/{id}/debrief` — сильную Claude/GPT Judge API с `teaching`, релевантными `course_sot/` и дословными репликами, выдаёт фактически обоснованные сильные действия/ошибки/рекомендации. Нельзя начислять школьные «экзаменационные» баллы; не наказывать за этапы, которых в короткой игре не было. Если отказ — zero Judge token cost. UI разрешает начать новую игру.
6. Галерея: только реально проверенные оригинальные игры как внешние ссылки + собственная карточка «Конфликты и переговоры». Независимая демонстрация, не официальный сайт.

## Приватность, надёжность, стоимость
- `OPENROUTER_API_KEY` использовать исключительно server-side, не в JS bundle/console. В .env.example только имена конфигурации; `PREMIUM_MODEL`, `CASE_MODEL`, `JUDGE_MODEL` независимы в конфиге, но могут все указывать на один и тот же сильный Claude Opus 5.5. Пользователь видит только 2 варианта roleplayer.
- `CASE_MODEL`, `PREMIUM_MODEL`, `JUDGE_MODEL`: конфиг без хардкода; для P0 старт с **`anthropic/claude-opus-5.5`**, альтернативно `openai/gpt-6-astra` по env. НИКОГДА не использовать `qwen/qwen3-32b` на премиальном пути. Модельное имя в интерфейсе соответствует реально настроенному PREMIUM_MODEL. API-провайдер OpenRouter совместимый, проверить structured JSON/разумные таймауты на живом тесте.
- Если нужен другой поставщик сильной модели, используем OpenAI-compatible adapter, а не новый SDK/API слой для каждого.
- Для public/mixed аудитория минимум упоминается в кейсе; **P1** выделенные реакции 1–2 свидетелей только от выбранного Roleplayer по смысловому триггеру, не третья модель и не мультиагентный оркестратор.
- Не слать все PDF и course transcripts на каждый ход; подбирать сжатые `compact_runtime_spec.yaml`, relevant `techniques.yaml` и `evaluation_rubric.yaml` для генерации и *опционального* debrief. Roleplayer видит только свою world/role/card/history без `teaching` и oracle. Без RAG для P0. Если API-модель не может быстро сформировать runtime JSON, repair retry, затем корректный fallback из TRAIN.
- No SQL overengineering. Единственный backend (FastAPI SQLite) и единый frontend, один deployable контейнер/сервис; все серверные секреты скрыты.
- No real user data hardcoded; никакой передачи DEV/TEST в интернет, публичный сайт или GitHub; никакой авторизации/профилей/платежей.
- Игра должна остаться рабочей при недоступности GPU: сильный Claude/GPT API mode — полнофункциональный основной путь, а LoRA явно disabled. Один deploy HTTPS без постоянного RTX.
- Два автопроверочных сценария API: конфликт, переговоры. При ручном smoke прогнать 6 сценариев, включая conflict_then_negotiation, mixed conflict и impossible; проверить optional Judge обе ветки и отсутствие вызова Judge при «Без оценки».

## Как работать
- **Первым коммитом** реализуй минимальный backend+UI и **один vertical slice** (генерация одного кейса, 3 сообщения, досрочное завершение, optional debrief/skip). Не полируй интерфейс до первого рабочего API цикла.
- В следующем коммите responsive UI и состояния ошибок/галерея.
- Дальше реальные smoke tests, лог ошибок; опубликуй на одном HTTPS-URL до последних 6 часов.
- Создай `README_DEMO.md` с точными командами запуска dev/deploy, env names, где менять модель, лимиты, что работает и что честно ещё не работает.
- В конце дай ссылку на локальный URL/демо URL только если действительно запущено; отчёт по проверенным сценариям (не «всё работает» без тестов).
- Никакого нового fine-tuning, 14B DEVs, 32B GPUs, плавающих зависимостей и переработки всего репозитория до утверждения работающей демонстрации. Зафиксированные эксперименты остаются в бэклоге, не блокируют премиальную Claude/GPT версию.
- Если блокирует внешний сайт игр, проси скриншоты; **разработка нового тренажёра не должна ждать**.

## Исполняемая проверка обязательных контрактов

- Отдельно тестировать `POST /api/sessions/{id}/finish`: не делает LLM-вызов, повторный finish идемпотентен, новые игровые ходы после finish отклоняются.
- При отказе от разбора пользователь может закрыть игру/сыграть ещё, **Judge API не вызывается** и ничего не списывается.
- При согласии `debrief` ровно один раз вызывает облачного Claude/GPT по педагогическому промпту; при сетевой ошибке retry только по явному нажатию.
- `MODEL_DEFENDER` — студент оказывает давление, ИИ защищает свои границы; `MODEL_MANIPULATOR` — студент защищается, ИИ оказывает давление. Нельзя поменять роли местами.
- Рандомизатор учитывает условную видимость полей (для чистых переговоров нет типа конфликта/роли манипулятора).
- `PREMIUM_MODEL` реально Claude/GPT по OpenRouter, на UI правильное название; если `LORA_BASE_URL` отсутствует, кастомный вариант disabled и не притворяется другой моделью.
- Смешанный **тип конфликта** и **Конфликт+переговоры** тестируются отдельно. Для высокой сложности эскалация условная/мотивированная, не автоматический переход в крик.
- Посетитель видит только публичные поля; секреты и `teaching`/условия уступок в браузер/лог клиента не передаются.

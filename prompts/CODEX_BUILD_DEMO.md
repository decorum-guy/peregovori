# Задача Codex №2 — рабочее full-stack демо переговорного тренажёра

**СРОЧНО: meeting demo ~15 октября 2026 вечером МСК, время ограничено.** Читай `docs/DEMO_48H.md` (главный приоритет), `docs/DESIGN_AUDIT.md` (если уже создан), `course_sot/compact_runtime_spec.yaml`, `schemas/case.schema.json`, `training/prepare_sft.py`, `docs/CASE_CONTRACT.md` и `docs/ARCHITECTURE.md`. ## Требования «сделать и показать», а не написать инфраструктуру
Построй полноэкранную адаптивную игру с оригинальным профессиональным UI, не выглядывающую из общей стилистики проверенной галереи:
1. Стартовый экран: имя (optional), режим **Конфликт/Переговоры**, тип личный/публичный/смешанный (для переговоров скрыть), сложность easy/medium/hard/extra_hard/impossible, сфера работа/семья/учёба/друзья/другое с собственным текстом, рандомизация параметров и кнопка начать.
2. Выбор реальных backend engine `Qwen3-32B` через OpenRouter и `Qwen3-8B · Дообученная` только при действующем `LORA_BASE_URL`; если нет, второй вариант честно disabled — никакой ложной «демонстрации QLoRA».
3. Запуск: через server-side `POST /api/sessions` вызывается case generator, выходит валидный JSON согласно существующей v1-схеме или мотивированно упрощённой runtime-схеме с конвертером/валидацией. При ошибке одна повторная попытка, затем проверенный static TRAIN-case для демо (не использовать DEV/TEST). Кейс не должен раскрываться целиком клиенту.
4. Игровой чат: слева имя персонажа, справа имя игрока; чистое форматирование, видимая карточка публичной обстановки/цели, `opponent.opening` первым, отправка и прокрутка, Enter/Shift+Enter, защита от повторной отправки, состояния загрузки и ошибок. Серверный `POST /api/sessions/{id}/message`, **отдельный** prompt roleplayer с world/public/opponent и строгим соблюдением hard_limits.
5. «Завершить» → `POST /api/sessions/{id}/debrief`, отдельный API Judge, основывается на фактах, компактном курсе, `teaching`, реальных репликах, примерах ошибок. Результат: сильные действия, ошибки, рекомендации. Никаких оценок экзамена от имени школы.
6. Галерея: только реально проверенные оригинальные игры как внешние ссылки + собственная карточка «Конфликты и переговоры». Независимая демонстрация, не официальный сайт.

## Приватность, надёжность, стоимость
- `OPENROUTER_API_KEY` использовать исключительно server-side, не в JS bundle/console. В .env.example только имена конфигурации.
- `CASE_MODEL`, `ROLEPLAY_API_MODEL`, `JUDGE_MODEL`: конфиг без хардкода; старт с `qwen/qwen3-32b` как доступной API-моделью, сменить можно через env.
- Если нужен другой поставщик сильной модели, используем OpenAI-compatible adapter, а не новый SDK/API слой для каждого.
- Для public/mixed аудитория минимум упоминается в кейсе; **P1** выделенные реакции толпы не чаще чем на смысловой триггер, не мультиагентный оркестратор.
- Не слать все PDF и course transcripts на каждый ход; подбирать сжатый `compact_runtime_spec.yaml` для генерации и debrief, roleplayer видит только role/card/history.
- No SQL overengineering. Единственный backend (FastAPI SQLite) и единый frontend, один deployable контейнер/сервис; все серверные секреты скрыты.
- No real user data hardcoded; никакой передачи DEV/TEST в интернет, публичный сайт или GitHub; никакой авторизации/профилей/платежей.
- Игра должна остаться рабочей при недоступности GPU: API mode — полнофункциональный основной путь.
- Два автопроверочных сценария API: конфликт, переговоры. При ручном smoke прогнать 6 сценариев, включая mixed и impossible.

## Как работать
- **Первым коммитом** реализуй минимальный backend+UI и **один vertical slice** (генерация одного кейса, 3 сообщения, debrief). Не полируй интерфейс до первого рабочего API цикла.
- В следующем коммите responsive UI и состояния ошибок/галерея.
- Дальше реальные smoke tests, лог ошибок; опубликуй на одном HTTPS-URL до последних 6 часов.
- Создай `README_DEMO.md` с точными командами запуска dev/deploy, env names, где менять модель, лимиты, что работает и что честно ещё не работает.
- В конце дай ссылку на локальный URL/демо URL только если действительно запущено; отчёт по проверенным сценариям (не «всё работает» без тестов).
- Никакого нового fine-tuning, 14B DEVs, 32B GPUs, плавающих зависимостей и переработки всего репозитория до утверждения работающей демонстрации.
- Если блокирует внешний сайт игр, проси скриншоты; **разработка нового тренажёра не должна ждать**.

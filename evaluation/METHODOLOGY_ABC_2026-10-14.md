# Methodology in Roleplayer: предзарегистрированный A/B/C на DEV

**Зафиксировано 2026-10-14, до платного запуска.** Демо меньше чем через сутки; приоритет — быстрый тест без новых эпох и без изменения TRAIN. Исходный Qwen3-8B QLoRA V2 (rank 16, две эпохи) и фиксированные DEV 25 кейсов / 75 проб. **Ветки сайта и экспериментальные скрипты НЕ сливаются автоматически.**

## Что выяснили при проверке готового сайта

Демо живёт в ветке `codex/design-audit-2026-10-13`, файлы `web/backend/app/prompts.py`, `service.py`, `models.py`, `web/README_DEMO.md`. Реализован маршрут React → FastAPI → генератор кейса → Roleplayer (премиальная Claude/GPT или Qwen) → Judge/Coach по отдельному запросу после игры. `generator_prompt()` **уже получает** выдержки `course_sot/compact_runtime_spec.yaml` и приёмы `course_sot/techniques.yaml`. Но `roleplay_messages()` опирается на `ROLEPLAY_RULES` и карточку персонажа и **не прикрепляет техники**. Judge получает `teaching`, Roleplayer — нет. Важно: не нарушить скрытые поля/разделение перспектива студента/персонажа, не меняем контракт runtime-кейса и не включаем режим обучения внутрь диалога.

### Предзарегистрированный эксперимент (функционирует в `main`)

| Вариант | Различие |
|---|---|
| **A** | Абсолютно идентичная прежнему DEV `model_context(case)` разметка, без изменений; **используем уже сохранённые 75 результатов 8B V2**, не расходуем GPU повторно. |
| **B** | A + общие правила из `course_sot/compact_runtime_spec.yaml`: различение цели конфликта и переговорной темы, эмоции/границы, этапы, публичная/личная фаза; короткий текст. |
| **C** | B + **ровно десять разных контекстно-релевантных приёмов** из `course_sot/techniques.yaml`, с названием, целью, условием входа, 1–2 шагами, предупреждением при наличии. |

**Нестрогость топ-10 обязательна:** полный репертуар ИИ **не ограничен** этими десятью приёмами, разрешены и ожидаются любые другие уместные переговорные действия. В C это прописано прямым явным текстом. Никаких «играй правильный приём студента» и цитирования методики вслух.

**Алгоритм отбора без LLM и без секретных ответов**: роль модели (`category`), тип сцены (`scenario`), открытый сюжет/факты, роль и эмоция собственного персонажа, последние 6 реплик. Список типов и стартовых приёмов задан воспроизводимо, далее проверяется соответствие реальным ID и условиям в YAML. Поля `teaching`, `oracle`, `focus_techniques`, `acceptable_outcomes` целиком игнорируются селектором; скрытая правильная техника студента никогда не передаётся Roleplayer. Никакой отдельной векторной БД и фоновой LLM-классификации.

### Научная честность / измерения

Это **внутренняя prompt ablation**, а не новое fine-tuning. A/B/C сравниваются на одном Qwen3-8B V2 adapter SHA и одних и тех же DEV SHA, greedy `max_new_tokens=192`, thinking выключен. Отличается **только добавленный текст системного контекста**; `max_prompt_tokens=6144` для B/C — технический допуск, а не намеренное усечение прежнего контекста. Скрипт прекращает запуск, если фактический промпт превышает лимит; при таком случае не подменять качество частичными результатами.

Нельзя сравнивать длину ответа или train loss вместо педагогической оценки. Таблица `blind_review_PRIVATE.csv` содержит ответы **под скрытыми метками X/Y/Z, разными для каждой пробы** и критерии из исходного DEV, `blind_key_PRIVATE.json` держать отдельно. Оценивать реплику 0/1/2 на предмет: 1) сохранения формальной/неформальной роли; 2) реакции на игрока и причинного хода; 3) условий уступки/жёстких границ; 4) фактов и арифметики; 5) публичной/личной фазы; 6) реалистичности и отсутствия мета-подсказок. **Не объявлять качество автоматически после генерации!** Из-за 3 проб на кейс использовать кластеризацию по 25 кейсам и фиксировать альтернативные исходы (B лучше A, C лучше B, регрессии).

**Важная оговорка по сайту:** архивный `model_context()` в `evaluation/run_gpu.py` **не буквально идентичен** системному шаблону `web/backend/app/prompts.py → roleplay_messages()` новой ветки. Этот быстрый тест изолирует эффект методологических дополнений на существующем научном DEV (сопоставим с 8B V1/V2/14B), но **не является готовой интеграционной проверкой всего веб-стека**. После выбора победителя перенести **только** обоснованное дополнение в demo Roleplayer через опциональный `ROLEPLAYER_METHODOLOGY_VARIANT` (по умолчанию A), проверить ролевую непроницаемость и прогнать реальные игровые сессии в ветке сайта. Без подтверждения не переключать демонстрацию.

## Когда и как запускать быстро

**СТРОГО после того, как текущая длинная тренировка 14B завершилась, отпустила RTX3090 и Intelion действительно остановился.** Никогда не делайте `git pull` во время живой тренировки 14B и не запускайте два GPU-теста одновременно. Текущий 14B может ещё писать данные на диск.

После завершения 14B и краткого повторного включения **того же VM11425 с прежним диском** (примерное лимитирование 85мин):

```bash
cd /root/peregovori
git switch main
git pull --ff-only
source .venv/bin/activate
python evaluation/methodology_context.py --validate-only
python training/upload_private_release.py check
bash training/start_methodology_abc_8b.sh
```

Запуск без переобучения делает только **150 новых ответов**: B 75 + C 75. A использует прежние 75 ответов QLoRA V2. В независимом `tmux methodology-abc-8b` логи: `tail -f eval_private/results/methodology_abc_8b_v2_review/pipeline.log`. Изменять `techniques.yaml` или `compact_runtime_spec.yaml` между B и C нельзя: в JSON-манифестах сверяются SHA-256. По результатам появится PRIVATE GitHub Release tag `methodology-abc-8b-v2-20261014-vm11425` внутри `decorum-guy/private-peregovori`, архив и SHA-256. При ошибке загрузки файлы сохраняются на диске, cloud API STOP/резервный watchdog всё равно задействуются. Убедитесь, что Intelion Auto-renew OFF и сервер получил реальный статус STOPPED.

Веб-сайт при этом **не переключается** с текущего Roleplayer и не теряет существующие настройки.

## Файлы

- `evaluation/methodology_context.py`: B/C из YAML, десять НЕ эксклюзивных техник, SHA методики, исключение oracle.
- `evaluation/run_gpu.py --prompt-variant A|B|C`: реальная генерация, прежний A по умолчанию остаётся неизменным.
- `evaluation/run_methodology_abc_and_stop.py`: повторно использует A, делает B/C, создаёт приватный бэкап и выключает VM.
- `training/start_methodology_abc_8b.sh`: отдельный безопасный launcher после завершения 14B.
- `evaluation/compare_methodology_abc.py`: проверка одинакового adapter/DEV/decoding, слепые X/Y/Z, критерии/поля оценщика.
- `evaluation/tests/test_methodology_context.py`: CPU-only проверки десяти реальных ID, неизменности A, детерминизма и игнорирования `teaching/oracle`.

## Stop/go критерий и дедлайн

Пока результатов 14B/нового prompt-A/B/C нет — **не платить за расширение TRAIN**. Если B или C растёт в качестве без роста ролевых ошибок — в demo зафиксировать способ подачи релевантной методики, затем перейти к проверке реальных длинных игр. Если не растёт — не переводить приложение на экспериментальный режим ради красивого названия, вернуться к размерам модели и внешнему state tracking.

Важно: **обучение/оценка на sealed TEST_A/B запрещены** до фиксации финальной системы. Не публиковать приватные DEV/слепой ключ.

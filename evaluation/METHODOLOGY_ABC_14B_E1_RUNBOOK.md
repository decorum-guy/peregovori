# Qwen3-14B E1 · быстрый методологический A/B/C без обучения

**Текущая выбранная модель — Qwen3-14B QLoRA после ПЕРВОЙ эпохи (112 optimizer steps, rank16).** По оценке на 75 DEV-пробах (один ИИ-оценщик) E1 имеет 1.280/2; E2 1.240/2; 8B E2 1.213/2. Малые разницы НЕ доказаны статистически. Мы тестируем влияние системного контекста, не выбираем по train loss.

**Запуск ещё не выполнен**, потому что Intelion сообщает, что GPU временно заняты. Готовая веб-игра в отдельной ветке `codex/design-audit-2026-10-13` не меняется, runtime-флаг ей пока не добавлен. Никаких дополнительных 14B-эпох и переобучения.

## A / B / C — неизменный 14B E1 checkpoint

| Вариант | Что получает Roleplayer | GPU |
|---|---|---|
| A | Старый промпт `training.prepare_sft.model_context` и **уже существующие 75 Qwen3-14B E1 DEV-ответов**, веса `qlora_14b_2ep/adapter_epoch_1` | 0 |
| B | А + компактные правила методологии из `course_sot/compact_runtime_spec.yaml`, сохранение границ/ролей | 75 ответов |
| C | B + **ровно 10 реальных релевантных техник** из `course_sot/techniques.yaml` | 75 ответов |

**Десять техник не являются ни ограничением, ни исчерпывающим списком.** Промпт прямо разрешает/рекомендует применять **любые другие уместные техники**, без навязывания метода игроку, педагогических комментариев и раскрытия `teaching`.

Выбор 10 техник детерминированный, без дополнительных вызовов LLM/RAG: по `category`, `scenario`, открытым фактам, роли персонажа, эмоции и последние шесть реплик. Поля `teaching`, `oracle`, закрытые эталоны ответов студенту **не используются** для отбора. Контекст, его SHA и выбранные ID сохраняются **приватно** для аудита.

**Контроль чистоты:** проверяем одинаковые `model = Qwen/Qwen3-14B`, SHA-256 фактического `adapter_epoch_1/*.safetensors` против прежнего `eval_private/results/qwen3_14b_e1/run_config.json`, `actual_epoch=1.0`, 75 одних и тех же DEV-probe IDs и входные SHA кейсов/проб; greedy decoding `max_new_tokens=192`, `enable_thinking=False`. Изменяется **только текст добавки** в системном промпте. Прежний A не перезаписывается. C/В получат больший лимит на ввод 6144 токена, но ни один промпт **не усечётся**: если превышает лимит, программа завершится с ошибкой.

### Как запустить, когда сервер снова станет доступен

Использовать **ту же VM Intelion №11425 и старый диск**, потому что там уже находятся 14B BASE/ E1/E2 и приватный DEV. **Только после завершения предыдущего 14B GPU-прогона**, не одновременно. В Intelion выключить auto-renew.

```bash
cd /root/peregovori
git switch main
git pull --ff-only
source .venv/bin/activate
bash training/start_methodology_abc_14b.sh
```

Скрипт **по умолчанию выбирает E1**; он проверит подлинность старого адаптера, наличие 75 ответов A, актуальные DEV SHA, доступ к **приватному** GitHub `decorum-guy/private-peregovori`, существование процессов GPU и watchdog, а затем поставит независимую автоостановку Intelion **через 85 минут**. Обучение модели **не производится**, только два 75-пробных инференса. При ошибке/бюджете архивируются доступные результаты, подаётся stop API (watchdog — резерв). После завершения убедиться, что провайдер показывает именно **STOPPED**; запрос stop может не успеть отразиться в UI. Если upload не прошёл, данные остаются на исходном диске VM.

Наблюдение:
```bash
tail -f eval_private/results/methodology_abc_14b_e1_review/pipeline.log
```

Итог — приватный GitHub Release `methodology-abc-14b-e1-20261014-vm11425` внутри `decorum-guy/private-peregovori`, archive `methodology_abc_14b_e1_private.tar.gz` + SHA и журнал. В архиве индивидуальные `lora.jsonl`, `run_config.json` (B/C), `prompt_evidence_PRIVATE.json`, `blind_review_PRIVATE.csv` и `blind_key_PRIVATE.json`. Не переносить в публичный GitHub.

### Если после E1 захочется отдельно проверить E2

Опционально, **лишь после оценки E1 A/B/C** и отдельного решения о финансировании:

```bash
bash training/start_methodology_abc_14b.sh --epoch 2
```

Получит собственный A из старых `qwen3_14b_e2`, другой adapter SHA, отдельный blind review и GitHub release. Не сравнивать B/C E1 с A E2: это разные веса, эксперимент методологически некорректен. Старый 8B launcher сохранён и жёстко закреплён на `--candidate 8b-e2`, **не запускать его сейчас**.

## Как судить после инференса

Скрипт **не делает вид, что посчитал семантическое качество**: CSV — заготовка для независимой слепой оценки A/B/C без раскрытия метки. По каждому из 75 ответов: 0/1/2 — смысловая реакция на студента; непротиворечивость роли и фактов; нарушение hard limits; сохранение публичной/личной фазы; арифметика/коммерческие условия; отсутствие подсказок о методе. Сначала выставить оценки X/Y/Z, **после** раскрыть `blind_key_PRIVATE.json`; 25 кейсов × 3 пробы, кластерный анализ по кейсу. Только после этого решить, переносить ли B/C в готовый веб-сайт.

**Внимание:** контекст прежнего офлайн `evaluation/run_gpu.py` близок по смыслу, но не идентичен `web/backend/app/prompts.py::roleplay_messages` в демо-ветке. Исследование показывает эффект методологии в нашем контролируемом DEV, **не заменяет отдельную проверку живого веб-диалога**. Запечатанные TEST_A/TEST_B пока не вскрывать.

## Проверки без платного сервера

GitHub Actions `.github/workflows/training-static-checks.yml` компилирует `training/`, `evaluation/`, проверяет bash-синтаксис и выполняет CPU unit tests на 10 реальных методах, идентичности A, отсутствии `teaching/oracle` leakage, воспроизводимости выбора и правильном кандидате E1.

Исходные файлы:
- `evaluation/run_methodology_abc_and_stop.py` — default `--candidate 14b-e1`, есть опциональные `14b-e2` / `8b-e2`.
- `training/start_methodology_abc_14b.sh` — безопасный one-command launcher 14B, эпоха 1 по умолчанию.
- `evaluation/run_gpu.py --prompt-variant B|C` — два 75-пробных вызова без изменения весов/DEV.
- `evaluation/compare_methodology_abc.py` — строгая проверка одинаковых весов и слепая таблица.
- `evaluation/methodology_context.py` — методология и десять НЕ эксклюзивных техник.
- `training/start_methodology_abc_8b.sh` — исторический скрипт 8B, явный флаг `--candidate 8b-e2`.

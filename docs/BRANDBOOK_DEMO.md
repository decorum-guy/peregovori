# Брендбук демо · «Линия решения»

**Этап 1 / 13.10.2026.** Исполнимое дизайн-ТЗ для самостоятельной игры **«Конфликты и переговоры»**. Приоритет функций — [DEMO_48H.md](DEMO_48H.md); доказательства исследования — [DESIGN_AUDIT.md](DESIGN_AUDIT.md). Все дизайнерские решения ниже — **[П] оригинальные предложения**, а не найденный брендбук школы. Исключения с маркировкой **[Н]** — проверенные факты. Frontend/backend здесь не реализованы.

## 1. Концепция и характер

**[П] Выбрана одна концепция — «Линия решения».** Две позиции, пространство между ними, право на границу и возможность найти следующий ход. Интеллектуально, живо, с умеренным эмоциональным напряжением; светлая среда помогает сохранять внимание к смыслу реплик. Сам разговор создаёт напряжение, интерфейс поддерживает устойчивость.

**[П]** Рассмотрены также «Переговорная сцена» (камерный театр, сливочный/винный, названия сцен) и «Развилка» (тактическая карта, кобальт, маршруты). Они не входят в выбранную систему. «Линия решения» быстрее реализуется, лучше обслуживает длинный русский текст и не обещает линейного прохождения методологии.

**[П]** Отличительный мотив: две тонкие смещённые угловые линии — синяя и терракотовая — вокруг свободного пространства. Это собственная простая геометрия: CSS или небольшой оригинальный SVG, без школы/логотипа, фото и сторонних иллюстраций. На старте мотив 120×72 px рядом с заголовком; в чате остаётся маленький фрагмент в шапке; в финале — спокойное горизонтальное соединение. Мотив декоративный, не показывает состояние оппонента или скрытое «напряжение».

**[П]** Тон: спокойное «вы», короткие действия, человеческие названия параметров. В диалоге тон определяется персонажем. Системные тексты не обвиняют: «Не удалось получить ответ. Ваша реплика сохранена»; при короткой игре — «Диалог короткий; выводы ограничены». Постоянная ненавязчивая подпись на старте/в галерее: «Независимый концепт для демонстрации». В финале: «Учебные рекомендации независимого прототипа». Регистрация не требуется.

## 2. Палитра и материалы

**[П]** Палитра создана для нашего тренажёра. Светлые прохладные поверхности, глубокий синий для действий и сообщений игрока, терракота для собственного знака и редкого смыслового акцента. Примерное распределение площади: 75% светлые поверхности, 20% текст/синий, ≤5% терракота. Цвета не меняются по режиму; отдельные «скины» не нужны.

|---|---|---|

На синей реплике — белый текст; на терракотовой мягкой поверхности — `ink`, при необходимости `accent` после проверки контраста. У декоративного разделителя контраст может быть ниже: им не обозначать границу единственного интерактивного контрола. Dark mode отложен.

[Данные расчёта](design_audit/2026-10-13/palette-contrast.json). Это проверка палитры, не сертификация ещё не созданного интерфейса.

Fallback: `Golos Text, system-ui, -apple-system, Segoe UI, sans-serif`. `font-display: swap`; при недоступной сети layout остаётся рабочим. Все основные тексты — обычный регистр, без узкого шрифта и постоянного CAPS.

## 4. Сетка, отступы и поверхности

**[П]** Шкала: **4, 8, 12, 16, 24, 32, 48, 64 px**. Мелкий gap 8; между связанными полями 16; между смысловыми группами 24. Высота контролов 44, CTA 48; все действия имеют touch area ≥44×44, даже при меньшей видимой иконке.

**[П]** Desktop ≥1024: оболочка max-width 1120, внешние поля минимум 32; старт max-width 960, форма ≤840; чат — боковой контекст 280 + gap 24 + остальная ширина диалогу (≈760 при широкой оболочке); разбор max-width 800. Планшет 768–1023: одна колонка, контекст над диалогом. Mobile <768: поля 16, все поверхности помещаются в доступную ширину; без горизонтального scroll.

**[П]** Радиусы: поля/кнопки 12; карточки 20; небольшие метки 8; пузырь сообщения 18 с внутренним нижним углом 6. Панель белая, тонкий `divider`; только поверхностям, требующим отделения, тень `0 8px 28px rgba(32,43,62,.07)`. Реплики без теней. Никакого точечного бумажного фона, scanlines, неонового свечения, пикселей, массивных чёрных рамок или KPI-панелей.

## 5. Минимальная система компонентов и состояний

| [П] Компонент | Вид / поведение |
|---|---|
| Кнопка primary | `primary` + белый; radius 12; hover `primaryHover`; pressed смещение 1 px; иконка необязательна |
| Кнопка secondary | Белый, текст `primary`, контур `controlLine`; используется для «Случайно» и повторов |
| Текстовое действие | `primary`, подчёркивание при hover; touch area 44; «Завершить» всегда читаемо в шапке |
| Radio / segmented | Светлый фон; выбранный — `surfaceSoft`, контур `primary` и галочка; `radiogroup` с keyboard-навигацией |
| Поле / select | Белый фон, `controlLine`, label снаружи; helper/error под полем; без placeholder вместо label |
| Карточка | Один уровень поверхности, заголовок и содержание; не вкладывать много панелей друг в друга |
| Message | Speaker над пузырём; собеседник слева белый, игрок справа синий; имя и выравнивание дублируют цвет |
| Notice | Значок + короткое сообщение + явный retry; черновик и успешная история сохранены |
| Disclosure | Контекст/факты на mobile, доступная кнопка с `aria-expanded` |

**[П]** Для каждого действия: normal, hover, focus-visible, pressed, disabled, loading. Focus: кольцо 2 px `accent`, offset 2, без обрезки. Disabled: мягкий фон и `muted`, не только уменьшение opacity; рядом причина, например «Сервер модели не подключён». Loading: текст действия и небольшой индикатор, ширина не прыгает; запрет повторной отправки. Ошибка — текстом, не вспышкой всей страницы. Радиогруппы не переключаются при случайном hover.

## 6. Старт: один компактный экран

**[П]** Один маршрут и одна форма, без мастера и регистрации. На 1440×900 все обычные настройки и запуск должны помещаться; ориентир содержимого ≤800 px по высоте. На 390×844 допустима умеренная вертикальная прокрутка одного экрана — не пытаться втиснуть все опции уменьшением текста. Короткая вводная: «Выберите ситуацию и попробуйте следующий ход в живом диалоге».

```text
← Игры                      Конфликты и переговоры
Название + одна строка смысла       [две линии]
┌────────────────────────────────────────────────┐
│ Конфликт | Переговоры | Конфликт + переговоры   │
│ Тип конфликта [select]  Сфера [select]          │
│ Ваша сторона [2 radio]  Сложность [select]      │
│ Имя, необязательно [input]                     │
│ Собеседник: [премиальная модель] [Qwen LoRA]    │
│ [Случайно]                     [Начать игру →] │
└────────────────────────────────────────────────┘
Независимый концепт для демонстрации
```

**[П]** Форма: padding 24 desktop / 16 mobile; колонки равной ширины, gap 16; label + контрол вместо длинного объяснения. На mobile режимы в двух колонках: первый и второй рядом, третий на всю ширину следующей строки; **всего три radio**, без дополнительного режима «Смешанный». Параметры в одной колонке; короткие пары типа/сферы допустимы рядом, только если подписи и select не обрезаются. CTA в нижней sticky-полосе 72 px + safe-area; содержимое имеет соответствующий нижний padding. На desktop CTA в форме.

| [П] Поле | Значения и обязательный контракт |
|---|---|
| Режим | **Конфликт / Переговоры / Конфликт + переговоры** → `conflict_only / negotiation_only / conflict_then_negotiation`. Остальные внутренние сценарии не добавлять в UI. |
| Тип конфликта | Личный / Публичный / Смешанный → `personal / public / mixed`; видим в обоих конфликтных режимах, скрыт в чистых переговорах. Смешанный — публичная и личная фазы, не третий режим. |
| Ваша сторона | Защищаю границы / Оказываю давление; только конфликтные режимы. Защита игрока → ИИ `MODEL_MANIPULATOR`; давление игрока → ИИ `MODEL_DEFENDER`. В чистых переговорах обе стороны договариваются. |
| Сложность | Лёгкая / Средняя / Сложная / Очень сложная / Желаемый исход закрыт → `easy / medium / hard / extra_hard / impossible`. Для последней короткий helper: один желаемый результат объективно недостижим; осмысленное завершение возможно. Причину ограничения кейса не раскрывать. |
| Сфера | Работа / Семья / Учёба / Друзья / Другое. «Другое» раскрывает необязательный двухстрочный ввод собственной темы. |
| Имя | Необязательно; пустое = «Вы». Не запрашивать личные контакты. |
| Модель собеседника | **Ровно два варианта:** `Claude Opus 5.5` (либо `GPT-6 Astra` вместо этого же слота по действующему backend-конфигу) и `Qwen3-8B · Дообученная`. Второй disabled с причиной, пока реальный LoRA endpoint не проверен. Название первого соответствует фактически настроенной модели. |

**[П]** Дефолты: «Конфликт + переговоры», личный, средняя, защита, работа, пустое имя, доступная премиальная модель. Они дизайнерские, не скрытая методологическая рекомендация.

**[П]** «Случайно» меняет режим, применимый тип, сложность, сферу и применимую сторону; сохраняет имя и модель. В чистых переговорах скрытые конфликтные значения не отправлять как действующие. Если случайно выпало «Другое», очистить прежнюю пользовательскую тему, оставить её необязательной. Это настройка формы без генерации/вызова модели; краткое подтверждение «Настройки обновлены» через live region, без конфетти.

**[П]** «Начать игру» → настоящая серверная генерация, loader «Готовим ситуацию…»; не показывать выдуманный процент. Сбой сохраняет все настройки, предлагает явный повтор. В резервном валидном сценарии честная компактная метка «Резервная ситуация»; не выдавать её за новую генерацию. Доступность premium/LoRA определяется сервером; модель в течение игры не меняется.

## 7. Игра: диалог занимает сцену

```text
← Игры    Название ситуации          [Завершить]
┌───────────────┐ ┌──────────────────────────────┐
│ Контекст      │ │ Анна                         │
│ Ваша роль     │ │ [реплика собеседника]         │
│ Ваша цель     │ │                         Вы   │
│ Известные     │ │               [ваша реплика] │
│ факты ▾       │ │                              │
│ Участники     │ │ [Ваш ответ…        ][→]       │
└───────────────┘ └──────────────────────────────┘
```

**[П]** Диалог — ≥65% рабочей ширины desktop; фон `canvas`, без лишней обводки вокруг всего потока. Публичный контекст — отдельная спокойная карточка. Отображать **только** `public.title/context/student_role/student_goal/known_facts` и явно публичные сведения об участниках. `world`, `private_facts`, `hard_limits`, `teaching`, скрытые мотивы и эталон не являются материалом UI. Не создавать новые «цели» из приватных полей. Если публичный контракт различает переговорную тему и конфликтную цель — подписать отдельно; иначе оставить единый `student_goal` без додумывания.

**[П]** На desktop цель сверху в карточке с тонкой терракотовой линией, контекст ниже, факты сворачиваются. На mobile — название и короткая видимая цель, затем «Ситуация и факты ▾»; полный контекст раскрыт при первом входе и легко сворачивается перед ответом. Крупный декоративный мотив исчезает. Пара участников аудитории — имена и роли в контексте P0. Если P1 появятся их реплики, они слева с отдельным speaker и нейтральным стилем; всё генерирует выбранная модель сессии.

**[П]** Пузырь: max-width 78% и max 620 px desktop; mobile max 88%. Padding 12×16; зазор speaker→bubble 4, между репликами 16. Оппонент: белый, `ink`, нижний левый угол 6. Игрок: `primary`, белый, нижний правый угол 6. Не использовать красный для «плохого» оппонента. Первое сообщение строго `opponent.opening`; модельная служебная речь и случайное приветствие не отображаются как ход.

**[П]** Composer: textarea 2 строки, рост до 6; send 44×44 с понятным accessible label. Desktop Enter отправляет, Shift+Enter переносит; во время IME-композиции Enter не отправляет. Mobile Enter — перенос, отправка явной кнопкой. Пустую/пробельную реплику отправить нельзя. Пока ответ ожидается, повторная отправка запрещена, черновик следующего ответа может редактироваться; индикатор «Собеседник отвечает…» не имитирует streaming. После ошибки последняя реплика имеет понятный статус; retry не добавляет второй экземпляр в историю.

**[П]** Автопрокрутка только если игрок находился у конца; при чтении истории остаётся на месте, появляется «Новое сообщение ↓». Ни рейтинг, ни таймер, ни счётчик обязательных ходов не отнимают внимание. Не рисовать шкалу эмоций и этапов без достоверного публичного состояния; этапы не линейны, конфликт может вернуться после переговоров.

**[П]** Высота приложения `100dvh`; composer в flex-раскладке, safe-area снизу. При открытии мобильной клавиатуры видны поле и отправка; header не раздувается. Длинная ситуация не выталкивает composer. Нужна будущая ручная проверка iOS/Android с клавиатурой и поворотом; эмуляция viewport этого не доказывает.

## 8. Завершение и разбор по согласию

**[П]** «Завершить» доступно всегда, включая ожидание ответа и первый ход. Действие закрывает сессию (`finish`), прекращает игровые реплики, **не вызывает Judge**. Пока закрытие сохраняется, кнопка остаётся на месте со статусом; ошибка закрытия сохраняет диалог и предлагает повтор. Поздний ответ персонажа не возвращает завершённую игру в активную.

**[П]** Обычное серверное завершение и досрочное ведут на одинаковый **отдельный финальный экран-предложение**:

```text
Диалог завершён
Хотите получить оценку и рекомендации?
[Получить разбор]   [Завершить без оценки]
```

**[П]** Не предвыбирать согласие и не запускать разбор при появлении экрана. «Завершить без оценки» → спокойное подтверждение + «Сыграть ещё», **zero Judge calls**. Повторная игра возвращает на старт с последними настройками для редактирования; это не автоматическая новая генерация. Восстановление разбора позже полезно, но P1.

**[П]** После «Получить разбор»: один loader «Разбираем диалог…», затем читаемый документ вместо дашборда. Повтор запроса только явный, после ошибки; уже полученный разбор не генерируется повторно при refresh. Четыре блока:

1. **Что произошло** — короткая сводка и ограничения наблюдения; ранний выход не считается автоматическим провалом.
2. **Сильные действия** — 1–3 конкретных хода, цитата/ссылка на фактическую реплику и объяснение эффекта; `success` только в значке/подписи.
3. **Что можно изменить** — конкретный риск/ошибка, фактическая реплика, объяснение; нейтральная поверхность, не красная простыня и не диагноз личности.
4. **Следующий ход** — один главный совет и пример альтернативной формулировки. Пример явно назван примером, не частью сыгранной истории.

**[П]** Цитаты визуально отделять от комментария тонкой линией; длинный текст переносится. Ссылка «Посмотреть реплику» раскрывает соответствующий фрагмент **сохранённого завершённого** диалога, не возобновляет игру. Никаких школьных экзаменационных баллов, процента победы, награды за соглашение любой ценой. Договорённость и качество действий — разные вещи; `impossible` не означает ошибку игрока. В короткой партии Judge оценивает лишь наблюдаемое, не требует всех этапов.

## 9. Галерея и соседство

**[П]** Своя галерея использует наш светлый стиль, заголовок и простые внешние карточки; не зеркалит зелёный каталог. Новая карточка **«Конфликты и переговоры»** выделена собственным двухлинейным мотивом и меткой «Независимый демо-концепт». Оригинальные игры — названия и ссылки из [GAMES_LINKS_VERIFIED.json](GAMES_LINKS_VERIFIED.json), без копирования их описаний, иконок или превью. Пометка «На сайте Soft Skills Lab ↗» ясно указывает внешнее назначение; конструктор может требовать вход. Не обещать доступность непроверенного игрового экрана.

**[П]** Совместимость с экосистемой: отдельная игра, понятная учебная задача, быстрый вход, заметный выбор, одна ведущая механика, видимые причины ошибок/блокировок. Самостоятельность: Golos Text, прохладный светлый фон, сланцевый/терракотовый дуэт, мягкие асимметричные реплики и геометрия границ. ## 10. Motion и перенос в код

Мотив на старте может один раз появиться за 240 ms; статический вариант достаточен. ## 11. Короткий handoff и приёмка

**[П]** Сначала функциональный P0 по `CODEX_BUILD_DEMO.md`, затем полировка в выбранном стиле. Достаточно перечисленных компонентов; без 3D, персонажного арта, отдельной дизайн-системной платформы и сложной игровой анимации. `UI.md` с заметками/подсказками — старый расширенный MVP; эти элементы P1, не добавлять боковую панель заметок в обязательный первый срез.

**[П]** На следующем этапе проверить:

- 1440×900, 390×844 и 320 px ширину: начало без огромной анкеты, нет обрезанных labels/горизонтального scroll; keyboard focus видим; touch ≥44.
- Три режима, условные тип/сторона, все пять сложностей, «Другое», имя; рандомизация сохраняет имя/модель. Ровно два слота моделей и честный disabled LoRA.
- `setup → generating → active → finishing → offer → judging → review` либо `offer → finished_without_review`. У каждого сетевого шага loading/error/retry без потери ввода. Refresh восстанавливает серверное состояние.
- Первое сообщение, различимые speakers, публика, длинные абзацы, прокрутка при чтении истории, отправка/IME/mobile keyboard; модель не меняется по ходу.
- Завершение до ответа, на первом ходе и после нескольких ходов; отсутствие Judge при finish/отказе; отдельное явное согласие; короткий диалог и `impossible` без ложной оценки «провал».
- Разбор с фактическими репликами, сильными/рискованными ходами и следующим шагом; отсутствие private/teaching/API secrets в клиенте; пометка независимого концепта.
- Соответствие токенам, работа системного fallback-шрифта и reduced motion. Проверять именно реальные состояния, не рисовать фиктивную работающую генерацию.

**[П]** Неизвестные активные экраны чужих игр не препятствуют этому ТЗ. API-модельные ID, цены и availability должен проверить агент реализации до запуска; здесь названия слотов взяты из согласованного контракта проекта.

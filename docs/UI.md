# Страница тренажёра — браузерный MVP

## Макет desktop

```text
┌───────────────────────────────────────────────────────────────────────┐
│ ПЕРЕГОВОРЫ  · Сценарий: ...  · Уровень HARD · Подсказки: по запросу   │
├────────────────────────────────────────────┬──────────────────────────┤
│ ЧАТ                                        │ МОИ ЗАМЕТКИ ▾            │
│                                            │ Тип конфликта [выбор]     │
│ Ситуация и моя роль (публичная часть)       │ Тема переговоров [текст] │
│                                            │ Цель конфликта  [текст]  │
│ Алексей: «...»                             │ Декодирование  [текст]   │
│                                            │ Этап           [выбор]   │
│ Я: «...»                                   │ Намерение/приём [текст]  │
│                                            │                          │
│                                            │ Переговорные заметки ▾   │
│                                            │ Интересы, ключевые точки │
│ [Написать следующую реплику.........]       │ Проблемы, базовая, L     │
│ [Отправить] [Подсказка] [Завершить/Разбор]  │ [Проверить мои заметки]  │
└────────────────────────────────────────────┴──────────────────────────┘
```

На мобильном: чат первым; заметки — раскрывающаяся панель/вкладка. UI остаётся доступным по клавиатуре.

## Что видит студент при старте

Название, свои роль и задачу, известные факты, первую реплику оппонента. Никаких приватных целей, скрытых условий уступки или эталона ответа. Сложность можно показывать; её причинные механизмы — нет.

## Боковая панель «Мои заметки»

Базовые поля: `conflict_present` (да/нет/не уверен), `conflict_type` (личный/публичный/смешанный/нет), `negotiation_topic`, `conflict_goal`, `decoding` (неформальная социальная роль), `current_stage` (эмоции, показать границы, защитить границы, этап 4, переговоры), `next_move`.

Дополнительный сворачиваемый раздел переговоров: интересы сторон, недостающая информация, проблемы, базовая точка, точка L, решения, аргументы, мостик.

Заметки — **ответы/гипотезы студента**, не инструкция roleplayer. Можно их проверять по отдельной кнопке. Подсказки включаются или выключаются на уровне сессии.

## Поведение игры

- Прогресс — по реальному состоянию, не по заранее заданному числу ходов.
- Корректная обработка эмоций может быстрее снять напряжение; неподходящая фраза может вызвать усиление давления.
- Это не механическое правило «не тот этап = отрицательный ответ»: реакцию определяют смысл реплики, характер и ограничения собеседника.
- После разрешения конфликта возможно **продолжение переговоров**; при новых нарушениях границ конфликт может вернуться.
- Можно закончить без соглашения. Уровень `impossible` не означает автоматического провала ученика.
- По завершении: отдельно «Что произошло», «Какие приёмы», «Заметки и эталон», «Альтернативные ходы».

## API (концептуальный минимум)

`GET /api/cases` — список публичных карточек.

`POST /api/sessions` — начать сессию по case_id и режиму подсказок.

`GET /api/sessions/{id}` — текущая публичная история и заметки.

`POST /api/sessions/{id}/message` — отправить реплику, получить ответ персонажа.

`PUT /api/sessions/{id}/notes` — сохранить заметки.

`POST /api/sessions/{id}/hint` — получить отдельную подсказку.

`POST /api/sessions/{id}/debrief` — завершить и показать разбор.

Это **проект интерфейса**, пока не реализованные маршруты.

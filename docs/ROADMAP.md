# Короткий план MVP

1. **Контракт и курс:** этот репозиторий — структура; `course_sot/` — методика. Валидатор проверяет контракт и формирует **новый** промпт генератора.
2. **Данные:** 8 партий × 25, каждый кейс независимо проверен; для раннего UI достаточно первых 10–25 принятых.
3. **Рабочий прототип:** FastAPI + SQLite + статическая адаптивная страница. Открыть кейс → чат → заметки → подсказка по запросу → разбор.
4. **Базовая модель:** Qwen3-8B через OpenAI-compatible endpoint. Критерии: не додумывать мир, удерживать роль/факты, честно сопротивляться или уступать, переходить к переговорам/этапу 4.
5. **QLoRA:** обучить только ролевой компонент на PASS-примерах. Сравнить с базовой на изолированных кейсах. Сохранить адаптер лишь при улучшении.
6. **Показ MVP:** доступная браузерная демоверсия с 3 видами сценариев, ручным выбором сложности, заметками и корректным разбором.

Никаких многосервисных backend, fine-tune генератора, отдельного постоянно активного judge-сервера или автоматического онлайн-генератора для первого релиза.

**Definition of Done:** студент может начать, сыграть и закончить кейс; приватные данные не показываются, заметки сохраняются, подсказки включаются явно, модель не рушит мир и даёт живые ответы, разбор методологически проверяем.

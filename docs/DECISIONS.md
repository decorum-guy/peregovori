# Решения · 2026-10-10

- Главное ограничение: **никакого overengineering**.
- Все 200 кейсов генерируются с нуля; старую B01 не мигрируем.
- 40% / 40% / 20% = 80 манипуляторов, 80 защитников, 40 чистых переговоров.
- Партия 25 = 10 / 10 / 5. Восемь партий. Только PASS идёт в зачёт.
- Один простой кейс-JSON; данные сессии/заметки отдельно в приложении.
- Генератор offline и ИИ-оппонент runtime — две основные роли моделей. Внешний валидатор проверяет dataset; Coach/Judge вызывается отдельно по запросу.
- Необходимый MVP: браузерная страница, чат, блок заметок, режим подсказок, итоговый разбор.
- Модель для первого исполнения: Qwen3-8B. QLoRA — эксперимент после базового теста.
- Source of truth по методологии: `course_sot/`. Классификации сценариев/сложности/режимов ИИ — продуктовые, а не термины лекций.
- Не кодировать ошибку студента как «неправильный список → автоматический провал». Смотрим контекст и реакцию.
- Допустимо отсутствие соглашения, сепарация, эскалация.
- Не добавлять микросервисы, графовые БД, агентные оркестраторы, RAG или сложный деплой без доказанной причины.

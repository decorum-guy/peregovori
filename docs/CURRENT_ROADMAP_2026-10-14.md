**Выполняет:** Codex. [Issue #3](https://github.com/decorum-guy/peregovori/issues/3).

- [ ] Флаг \`CLOUD_ROLEPLAY_PROMPT_VARIANT=A|B|C\`, default **A**, только **cloud Roleplayer**. Не менять Generator, Judge, Qwen или UI.
- [ ] A = текущий исходный системный промпт; B = короткая role-aware методология; C = B + **10 реальных релевантных, явно НЕ исключающих иные приёмы техник**. Разрешать любые уместные инструменты, никогда не включать \`teaching/oracle\` и не выдавать роль преподавателя.
- [ ] **ВАЖНО:** на 14B QLoRA прямые 10 техник дали отрицательный результат A=1.187/B=1.133/C=1.040 по одному слепому DEV-судье. **Это не результат Claude. У Claude эффект неизвестен и требует отдельного реального теста.**
- [ ] Использовать **один и тот же неизменный runtime case** и одинаковые первые ходы для сравнения A/B/C, избегать 9 повторных генераций кейса через Opus. Для controlled replay допустим dev-only harness с **настоящим** OpenRouter, но не считать его заменой хотя бы одного реального браузерного прохода.
- [ ] Сначала минимальные качественные стресс-пробы, затем продлевать лишь если появились неоднозначности. Слепой сравнительный разбор. Не менять default без evidence и одобрения владельца.
- [ ] Результат: \`docs/CLOUD_ROLEPLAYER_METHODS_PLAYTEST_REPORT.md\` в веб-ветке, сохранённый default A или обоснованно одобренный переключатель, SHA изменения и кнопка отката.

### P0-3. API COST GATE — нельзя неоправданно расходовать бюджет

**Наблюдение владельца:** одна игра ≈ **$0.30**; это может сильно зависеть от длины, количества генераций, Judge и выбранной модели. Пока НЕТ подтверждённой разбивки на компоненты.

- [ ] Замерить \`input/output tokens\`, фактическую цену OpenRouter и latency **отдельно для Generator / Roleplayer (каждый ход) / Judge**, имя модели, сценарий, число ходов. Записывать только агрегированную/санитизированную телеметрию: **без API key, raw prompt, пользовательских личных данных или скрытых мотивов**.
- [ ] **Baseline 3 режима прежде расширенных A/B/C.** Сравнения использовать один сохранённый фиктивный кейс/историю, без повторного дорогого Generator и Judge. Judge запускать только для проверки явного согласия/педагогической оценки, не после каждой пробной партии.
- [ ] Рекомендованный **предельный бюджет новых платных вызовов Claude для текущей качественной проверки: $5**, не включая уже потраченное; это **предложение, а не подтверждённый пользователем лимит**. До нового расхода выше лимита запросить согласие владельца. GPU-бюджет владельца ≈5000 ₽ **отдельный**, не смешивать.
- [ ] Если Claude A демонстрирует P0-баг — исправить его, а не тратить API на 3 варианта. Если B явно регрессирует — не оплачивать полный C без информативной цели.
- [ ] Возможный будущий cost-cut: опционально дешевле Case Generator и/или Judge, **НО сначала слепо доказать качество** и не менять сильную модель в середине A/B/C. Не экономить ценой невалидных кейсов/некачественного разбора.
- [ ] Реальную стоимость каждого режима представить в отчёте с диапазоном по длине партии; $0.30 — предварительный ориентир, не гарантированная фиксированная цена.

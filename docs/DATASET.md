# Генерация и проверка: 8 партий × 25

| | За партию | Итог |
|---|---:|---:|
| `MODEL_MANIPULATOR`: ИИ давит | 10 | 80 |
| `MODEL_DEFENDER`: ИИ защищается | 10 | 80 |
| `MODEL_NEGOTIATOR`: чистые переговоры | 5 | 40 |
| **Всего** | **25** | **200** |

B01 = C001–C025, B02 = C026–C050, …, B08 = C176–C200. Все новые. Прежние 50 не мигрируем и не считаем.

## Цикл одной партии

1. Генератор получает все `course_sot/`, архитектуру и `schemas/case.schema.json`. Генерирует 25 кейсов с разными сюжетами и механиками; допускается физически делить выход на файлы по объёму, но считать одной партией.
2. **Другая** LLM-валидация + исполняемая JSON Schema-проверка. Каждый кейс: `PASS / REVISE / REJECT`. Отчёт содержит ID, точную ошибку, основание, корректирующее действие.
3. Возвращаем генератору только фидбек: исправить `REVISE`; заменить `REJECT` **новым** кейсом той же роли; не трогать `PASS`.
4. Исправленные версии проходят **повторную** независимую проверку. Партия завершена, только когда есть 25 PASS с балансом 10/10/5.
5. Только потом открываем следующую партию. Новая учитывает системные ошибки предыдущей.

Генератор и валидатор не могут сами объявлять «всё корректно» без чтения материалов. Проверка JSON Schema без выполнения кода не должна называться программной.

## Что специально покрыть

Личные, публичные, смешанные конфликты; эмоции; ненамеренные нарушения; сопротивление и смена приёмов; устойчивые манипуляторы; этап 4; конфликты, переходящие в содержательные переговоры; отдельные чистые переговоры; работа с интересами, проблемами, декомпозицией, аргументацией и мостиком.

Каждый из пяти уровней сложности должен встречаться. Нельзя кодировать `extra_hard` как «повторить отказ 5 раз», а `impossible` как абсурдное упрямство. Исход определяется миром, мотивами и действиями студента. Быстрое правильное завершение допустимо.

Доля длинных сценариев должна быть заметной, но жёсткой длины нет. Требуются варианты эскалации/сепарации, не только победы через одну «правильную» фразу.

Только PASS-кейсы компилируются в SFT. Train/validation/test разделяются **по case_id**.

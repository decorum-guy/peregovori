# QLoRA: первый практический запуск (RTX 3090 24 GB)

**Текущий статус:** конвертер и код обучения подготовлены. TRAIN проверен по всем восьми файлам; обучение на сервере еще НЕ выполнялось. Этот эксперимент относится **только к Roleplayer**, не к Judge/Coach.

## Что зафиксировано и что НЕ меняем

Источник: \`dataset/exports/peregovori_train_200_cases.jsonl\` и соседний manifest. Все **200** кейсов предназначены для обучения; приватные DEV/TEST сюда не копировать. Исходный SHA-256 записан в manifest, а конвертер проверяет его перед любой записью.

В исходных данных: **1 095** сообщений assistant, но из них **200** — заданные кейсом вступительные фразы. Они показываются пользователю напрямую и не нуждаются в прогнозировании нейросетью. Конвертер создаёт **895** примеров вида:

\`\`\`json
{
  "prompt": [
    {"role": "system", "content": "инструкция + факты и мотивация своего персонажа"},
    {"role": "assistant", "content": "стартовая реплика"},
    {"role": "user", "content": "ответ студента"}
  ],
  "completion": [
    {"role": "assistant", "content": "следующая реплика персонажа"}
  ]
}
\`\`\`

По мере развития беседы \`prompt\` включает реальные предшествующие ходы. В нём **нет** \`teaching\`, \`evaluation rubric\`, \`oracle\` или эталонной инструкции студенту. Модель вправе получать приватные мотивы **своего** персонажа, но не должна произносить их как служебную разметку. Никакого CoT/thinking в target.

## Подготовка БЕЗ GPU (можно до запуска машины)

При уже клонированном репозитории:

\`\`\`bash
cd peregovori
python3 training/prepare_sft.py
\`\`\`

В норме получите \`training/derived/peregovori_sft.jsonl\` (**895** строк) и \`training/derived/peregovori_sft_report.json\`. Файлы генерируются детерминированно, исходный TRAIN не меняется. Если SHA не сошёлся — **останавливаемся**.

## На облачном Ubuntu-сервере

Пока экземпляр остановлен, сначала подготовьте команды, потом запустите его. Для новых образов с GPU полезен образ Ubuntu 22.04 + CUDA 12.8; наличие CUDA Toolkit не равно наличию рабочего PyTorch.

\`\`\`bash
nvidia-smi
python3 --version
git clone https://github.com/decorum-guy/peregovori.git
cd peregovori
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
\`\`\`

Нужно Python 3.10–3.12. Если CUDA-PyTorch не предустановлен в виртуальном окружении, установите подходящий wheel (для образа CUDA 12.8, если драйвер совместим):

\`\`\`bash
pip install torch --index-url https://download.pytorch.org/whl/cu128
\`\`\`

Затем:

\`\`\`bash
pip install "transformers>=4.51,<5" "peft>=0.15" accelerate bitsandbytes datasets safetensors
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
python training/prepare_sft.py
python training/train_qlora.py --dry-run
\`\`\`

Последняя команда загружает **только токенизатор**, проверяет 895 примеров, размер контекстов, ненулевую маску supervised-токенов. При ошибке **не запускаем** обучение.

## Сначала короткий тест, потом полный

\`\`\`bash
# Очень короткий smoke-test: убедиться, что QLoRA действительно шагает и сохраняется
python training/train_qlora.py --max-steps 10 --output training/outputs/smoke

# Если smoke завершился успешно, первый полноценный проход по данным
python training/train_qlora.py --epochs 1 --output training/outputs/qlora_v1
\`\`\`

Начальные настройки: Qwen/Qwen3-8B, 4-bit NF4, LoRA rank 16, alpha 32, batch=1,
accumulation=8, max_length=3072, learning_rate=1e-4, 1 эпоха. Длинная история при нехватке
контекста сокращается удалением **самых старых завершенных пар реплик**; системные
правила, персонаж, вступление и последний ход студента сохраняются.

**Критическая деталь Qwen3:** шаблон применяется с \`enable_thinking=False\`. Обучаем только
токены целевого ответа assistant; предшествующие реплики и system имеют loss \`-100\`.
Используется стандартный Transformers + PEFT; он проще отладки, чем несколько
слоёв несовместимых преобразований через Unsloth/TRL. Ускорение можно добавить позже.

## Почему 1 эпоха для начала

895 целевых реплик — небольшой SFT. Несколько эпох могут увеличить переобучение и
сделать сопротивление оппонента шаблонным. Это экспериментальная настройка, а не
доказанный оптимум. После короткого обучения сравниваем базовую и LoRA на **DEV**,
подбираем при необходимости только по DEV; TEST_A/B открываем для финального сравнения.

**Не обещаем**, что двух часов оплаченной аренды достаточно на загрузку, установку,
проверку и 1 эпоху. Контролируйте время и доступный баланс.

## Результат и бэкап

После полной тренировки появится \`training/outputs/qlora_v1/adapter\` с LoRA-файлами
и tokenizer. Это **не** самодостаточные 8B-веса: для инференса нужен тот же
\`Qwen/Qwen3-8B\` + адаптер.

Обязательно **скачайте адаптер, лог и отчет о конвертации** через JupyterLab/SCP, прежде
чем удалять сервер или диск. Остановка сервера и удаление диска — разные операции;
уточните правила тарифа в Intelion Cloud.

Дообучение не заменяет внешний \`session state\`: следить за арифметикой,
переходами и тайными фактами должен также backend.

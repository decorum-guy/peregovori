## Научная гипотеза

Три кандидата на ОДНОМ frozen DEV (25 кейсов, 75 проб):
- Qwen3-8B BASE — 75 старых ответов;
- Qwen3-8B QLoRA V1 rank16, 1 эпоха — 75 старых ответов;
- Qwen3-8B QLoRA V2 rank16, **2 свежие эпохи с базовой модели** — только 75 новых ответов.

Оригинальный TRAIN 200 кейсов/895 SFT целей не менять. DEV не учить. TEST_A и TEST_B запечатаны. Скрипт создаёт слепой тройной CSV для последующего независимого Judge, **не имитирует** качество по формальным метрикам.

## Запуск на сервере по SSH

После включения СУЩЕСТВУЮЩЕЙ Intelion VM:

```bash
cd /root/peregovori
git switch main
git pull --ff-only
bash training/start_8b_2epochs.sh
```

Если переключение ветки остановлено из-за локальных изменений — разберитесь с ними, НЕ делать reset --hard.

Что делает launcher: проверяет 75+75 исторических ответов, SHA frozen DEV, старый адаптер и наличие CUDA; архивирует неактивный прошлый deadline, вооружает 100-минутный watchdog Intelion API, стартует отдельную сессию tmux; обучает до двух эпох с нуля с отдельным output; сохраняет реальный actual_epoch; если прогон полный — производит 75 DEV-ответов только новой LoRA и формирует blind CSV A/B/C; упаковывает результаты и вызывает stop Intelion API, при успехе либо ошибке. Таймер страховочный, не провайдерское расписание. Не запускать одновременно другое обучение.

Мониторинг (Ctrl+C прекращает чтение лога, НЕ обучение):

```bash
tail -f training/outputs/qlora_v2_e2/pipeline.log
```

Финальный статус остановки проверить в Intelion Cloud; само сообщение «Stop command sent» ещё не означает подтверждённую остановку.
